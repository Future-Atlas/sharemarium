# 企業向け広告枠の仕様案（未実装・未販売）

本書は検討用。料金・契約条件の確定、企業への販売、配信コード、利用者の新たな追跡・属性収集は行わない。既存のAdSenseとAmazonアソシエイトは、企業と直接契約する広告とは別に管理する。サブスクの公開や設定変更も行わない。

## 1. 確認済みの方向性

- 将来、企業に広告枠を直接販売する。
- コード実装の前に、広告枠・販売方式・計測方法を固める。
- 過去チャットの構想は、条件フィルター、関連性、予測CTR、配信ペース、探索を組み合わせるもの。
- 読書ジャンル割合（例: ミステリー0.7、恋愛0.3）は合計1の連続値であり、0/1のダミー変数と区別する。
- 過去チャットのCPMや最低出稿額は提案であり、契約済み料金・実績ではない。

## 2. 広告枠の候補（配置は最終確認が必要）

| 枠ID案 | 配置案 | 初期優先度 |
| --- | --- | --- |
| home_sponsor | ホームの専用スポンサー枠 | 最初の候補 |
| search_sponsor | 検索欄の下・書籍候補一覧の上。マイページの投稿用検索も同じ方針 | 次の候補 |
| timeline_sponsor | タイムラインの通常投稿10件ごと。空一覧には出さない | 後で追加 |

共通の表示案:

- カード上部に高コントラストで「広告」、広告主名、画像またはテキスト、遷移先ボタンを表示。
- 枠はダークモードで白、ライトモードで黒。スマホでもはみ出さないサイズ制限を設ける。
- 投稿と誤認しない専用カードとし、返信・リアクション・ユーザープロフィールへの遷移を設けない。
- ポップアップ、強制遷移、クリックを促す報酬、操作ボタンに重なる広告は採用しない。
- 同じ枠にAdSenseと直接広告を同時表示しない。企業の独占契約を設定するなら、その枠では競合する配信を停止する。
- 広告が未登録・期間外・取得失敗の場合は空枠を隠す。失敗で書籍や投稿の表示を妨げない。

## 3. 販売方式の提案

初期は「掲載期間を決めた固定料金」を推奨案とする。表示数の実績がない段階では保証表示数を約束せず、期間と枠、ローテーションか独占かを明記する。

実績が蓄積した後にCPM契約を追加する。CPC契約は不正クリック対策と計測が整うまで保留する。

- CPM料金 = 請求対象の表示回数 / 1,000 × CPM単価。
- 在庫の予測 = MAU × 一人当たり月間広告表示回数。販売可能量はさらに配信対象・広告ブロック・実表示率・既存契約の予約量を考慮する。
- 過去チャットの例: 通常CPM 1,000円、ジャンル指定1,500円、成人年齢層＋ジャンル2,000円、創刊スポンサー月1万〜3万円。すべて未確定。年齢による配信は初期案に含めない。
- MAUだけから売上や到達人数を保証しない。CPMの計算では必ず1,000で割る。
- 税込/税抜、最低出稿額、素材制作費、入金期限、未達時の延長/返金、取消・掲載停止、審査基準、競合排除は別途決定する。

## 4. 計測方法の提案

「配信要求」「描画」「実際に見えた表示」「クリック」を分ける。

| 指標 | 初期定義案 |
| --- | --- |
| 有効表示 | 広告面積の50%以上が連続1秒画面内にあり、タブが前面のとき。広告インスタンスにつき1回のみ |
| 有効クリック | 表示中の広告に対する本人のリンク操作。二重送信を除外し、ボット・運営者テストを請求対象外にする |
| CTR | 有効クリック数 / 有効表示数。分母0は未算出 |
| 月間表示 | 当月の有効表示合計。集計タイムゾーンを日本時間に統一 |
| 到達人数 | 初期は測定しない。識別子を導入せず、表示回数から人数を推定して実測と表示しない |

50%・1秒は契約用に採用するか確認が必要な提案であり、外部計測機関による認証を意味しない。

必要な技術設計:

- クライアントの回数をそのまま請求根拠にせず、サーバー発行の配信IDでイベントを照合・重複排除する。
- 不正送信・リプレイ・過剰クリックの検知、レート制限、運営者のテスト除外を設ける。
- 表示上限や予算消化はサーバーで原子的に判定し、同時アクセスで超過しないよう予約・確定・期限切れを扱う。
- 広告主へのレポートは広告/枠/日別の集計を基本とし、個々のユーザーID・生年月日・閲覧履歴を渡さない。
- Cookie等の端末識別子、ログ保存期間、アクセス権、削除方法は配信前に確定する。
- 初期の同一広告の出しすぎ対策は一時的なセッション内上限を候補とする。ユーザー横断・端末横断の回数保証はしない。

## 5. 最適化の導入段階

### 初期: 個人情報を使わないページ単位の配信

1. 審査済み、掲載期間内、対象枠、配信量/予算内の広告だけを残す。
2. 現在のページ/書籍ジャンルに合う広告と全体向け広告を候補にする。
3. 契約の残り期間と残り配信量から配信ペースを補正する。
4. 候補内でランダム/重み付きローテーションし、新しい広告にも機会を与える。
5. 表示・クリックと、どのルールで選んだかを計測する。

初期は成年向け広告を受け付けない案とする。生年月日・性別・本棚・個人閲覧履歴を広告選択へ新たに流用しない。

### 次期: 実績に基づく最適化

- 広告×ページジャンルの集計からThompson Sampling等を比較検証する。
- CPCを導入する場合、期待収益/表示 = 予測CTR × CPC。CPMなら CPM / 1,000。
- 探索と契約消化を両立し、クリック率だけが高い広告に偏らせない。
- 重みや探索率は検証で決める。スコアだけで保証配信を達成できるとは扱わず、契約枠の予約・配信制御を分ける。
- 過去チャットの「月5万回」等は目安であって、学習開始の固定基準にはしない。広告ごとのサンプル数と結果の不確実性で判断する。

### 将来: 個人別の最適化（別承認が必要）

- 利用目的・同意/オプトアウト・未成年の扱いを整理し、必要な文書や法務確認を終えてから検討する。
- 年齢を使う場合も広告処理に正確な生年月日を渡さない。性別は必須収集・推測しない。
- 嗜好ベクトルを使う場合も、政治・宗教・健康等のセンシティブな属性を読書履歴から推測する用途には使わない。
- 広告主への個人データの提供は行わず、集計でも少人数の区分から個人が分かることを避ける。

## 6. 実装へ進む前に決める項目

1. 最初の広告枠: ホームのみ / ホーム＋検索 / タイムラインも含む。
2. 最初の販売方式: 固定期間料金 / CPM。金額・税表記・契約期間・独占の有無。
3. 広告素材: 画像・見出し・説明・CTAのサイズと文字数、遷移先URLの審査。
4. 表示・クリックの契約上の定義、除外条件、レポート頻度、未達や障害の扱い。
5. キャンペーン登録・審査・一時停止を誰が操作するか。
6. 保存する計測情報と保存期間、必要な文書・法務確認、公開承認。

この6点を確定してから、データモデル、権限、配信API、カードUI、計測、管理/レポート画面の順に実装する。
